# 게임 변경점과 확인할 내용 — 2026-10-30

이 문서는 마지막 플레이 피드백의 반영 내용과 10월 29~30일 점검 결과를 한곳에 모은 사용자 확인용 기록이다. 검사 전용 실행 파일과 실제 플레이용 빌드를 구분한다. 10월 30일 후속 검증까지 완료했다.

## 마지막 게임 작업에서 바뀐 점

사용자가 마지막에 지적했던 화면·대기실 관련 수정은 다음과 같다.

- 규칙 설명창을 열면 조준 링뿐 아니라 예상 착탄 표식도 숨긴다. 위치 안내의 글자 크기·간격·아이콘 행을 맞췄다. 예상 착탄 X는 작은 모서리와 중앙 점으로 교체했다.
- 공유 게시판의 4개 주제 표적을 천장 위로 옮겼다. 관통 라이플로 맞힐 때만 주제가 바뀌며 일반탄·샷건·유탄은 바꾸지 않는다. 개인 규칙 설명 버튼은 다른 사람의 게시판 조작과 별개로 사용할 수 있다.
- 머리 위 이름을 더 올리고 본인 밑줄을 없앴다. 본인 삼각 표시, 준비 배지, 탄종 그림/잔탄, 스태미나의 간격을 조정했다. 좌측 명단은 P 배지·이름·본인/방장/AI·준비 상태를 카드 안에 묶었다.
- 사람과 AI가 몸으로 서로 미는 원인을 수정했다. 플레이어끼리 통과하며, 사격 피해·사망·부활과 지형/몹 충돌은 유지한다.
- 앞선 AI 보강에는 특수탄 선택·파밍·몹 공격, 피격 공격자 우선 반응, 전투 중 점프, 점령 우선 판단, 쉬움/보통/어려움 선택이 포함되어 있다. 최종 사용감은 실제 플레이로 확인해야 한다.

관련 상세 기록: `GUIDE-ROOM-REFINE-2026-10-28.ko.md`, `GUIDE-BOARD-2026-10-28.ko.md`, `READABILITY-AI-2026-10-28.ko.md`.

## 이번 검사 중 추가로 고친 점

1. **AI 경로:** 하단 중앙 해킹 지점으로 가는 점프 연결이 끊긴 부분을 발견했다. 플레이어의 실제 점프 속도·중력·추가 점프를 사용해 연결을 검사하고, 몸/머리 통과 및 다리의 실제 바닥 높이를 반영하도록 수정했다. 플레이어의 이동·점프 수치를 높인 것은 아니다.
2. **웹 혼자 연습/튜토리얼:** 브라우저가 직접 UDP 서버를 열 수 없는 문제에 대응해, 이 두 오프라인 모드에서만 무소켓 내부 호스트를 사용한다. 온라인은 UnityTransport/Relay를 사용한다. 웹의 종료 버튼을 숨기고 방 목록의 지연 대기를 프레임 기반으로 바꿨다.
3. **작은 화면:** 하단 대기실 버튼과 탄약 HUD가 겹치지 않도록 패널을 배치했다. 작은 화면에서는 참가자 명단을 접어 두고 버튼으로 펼치게 했다. 기본 접힌 상태에서 천장 표적·게시판 제목·조작 카드가 보인다. 1366×768 이상에서는 기존 전체 명단을 유지한다.
4. **웹 입력:** 닉네임/방 이름을 누르면 브라우저 입력창에서 편집한다. 한글 조합 중 Enter가 저장으로 처리되지 않도록 하고, 저장/적용과 취소를 분리했다. 닉네임은 기존 최대 12자 정리·저장 경로를 사용한다. Windows의 기존 텍스트 입력 방식은 유지한다.
5. **웹 혼합 접속:** 참가자가 자신의 플랫폼에 맞는 Relay 프로토콜을 지정하게 했다. 설치 SDK가 별도 지정 없이 방장의 프로토콜을 따르는 경우, Windows 방장의 DTLS를 웹 참가자가 사용할 수 있는 WSS로 선택하지 못할 수 있었다. 웹 온라인 연결 전에 UnityTransport의 WebSocket 옵션도 켠다. 실제 혼합 접속 양방향과 수정 후 오류 해소를 확인했다.

일반탄은 여전히 **12발 / 마지막 발사 1초 후 / 초당 4발 자동 충전**이다. 일괄 충전으로 바꾸지 않았다. 라이플 피해 30, 보호막 최대 50/중첩 없음 등 기존 밸런스와 음원·맵 충돌·캐릭터 크기도 이번 검사에서 변경하지 않았다. 채팅, 맵/랜덤 선택, 8인·팀전은 아직 아이디어/후속 범위다.

## 직접 확인하면 되는 순서

1. **대기실:** 닉네임이 한 줄로 보이는지, 이름과 머리/준비/탄종이 겹치지 않는지, 본인 구분과 명단 카드가 읽기 편한지 본다. 작은 화면에서는 명단 펼치기/접기를 확인한다.
2. **가이드:** 일반탄으로 천장 표적을 쏴도 바뀌지 않고 라이플만 바꾸는지, 개인 규칙창의 글자가 잘리지 않고 착탄 표식이 사라지는지 확인한다.
3. **AI와 한 경기:** 중앙 아래 점령 지점으로 오는지, 이동 중 걸리는 곳이 없는지, 뒤에서 맞았을 때 반응/점프/특수탄·파밍 판단이 납득되는지 본다. 난이도별 재미와 강함은 사람의 판단이 필요하다.
4. **전투 흐름:** 일반탄 충전 대기와 특수탄 사용의 흐름, 일반탄/라이플/유탄의 청감, 스태미나 이동감, 부활 보호의 보임새를 확인한다. 자동 검사가 소리 취향이나 재미까지 평가한 것은 아니다.
5. **실제 두 PC:** 같은 최신 빌드로 방 이름/닉네임/준비, 사격·아이템·점령, 사망/관전/부활, 종료 문구→결과→대기방 복귀와 재경기를 확인한다. 통신 지연이 있는 환경과 접속 끊김도 남은 실제 사용 조건이다.
6. **웹을 배포할 때:** 실제 한영키로 한글 조합·수정·저장을 확인한다. 전체화면, 소리, 호스트의 탭 전환, Windows와의 접속, Unity Play 로더/압축 헤더를 확인한다. 로컬 웹 실행이 곧 Unity Play 업로드 완료를 뜻하지 않는다.

## 현재 실행 파일

실제 플레이용은 `Builds/BulletShot/2DNetcodeGame.exe`다. 최신 소스 일반 Windows64 Mono 빌드는 오류 0/기존 경고 5, 122.184초, 710,045,354 bytes로 완료했다(Development 꺼짐). 검사 클래스 3종이 일반 DLL에서 제외됨을 확인했다.

웹 확인용은 `Builds/WebFollowup-20261030/`다. 최종 Web 빌드는 오류 0/기존 경고 5, 327.894초, 153,351,407 bytes다. 로컬 검사를 위한 비압축 출력이므로 실제 배포용 Brotli 출력과 크기를 직접 비교하지 않는다. Unity Play에 업로드하지 않았다. 프로젝트 설정은 Windows64/Brotli로 복원했다.

시험 방 삭제, 별도 검사 프로필 토큰 정리, 숨김 검사 실행 파일·로컬 서버·탭 종료를 확인했다. 검사 전용 `ContinueAudit`/`RelayAudit`/`PerformanceAudit` 실행 파일은 배포용이 아니다. 기존 미커밋 변경은 보존했으며 커밋·푸시는 하지 않았다. 일부 앞선 빌드의 검사 API 시간초과 및 파일 잠금 오류는 상세 보고서에 실패 기록까지 남겼다. 최종 성공 결과와 구분한다.
