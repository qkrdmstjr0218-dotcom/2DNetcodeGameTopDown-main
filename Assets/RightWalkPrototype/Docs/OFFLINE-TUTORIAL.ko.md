### 집 Editor 프레임 지연 조사

가상 플레이어2/3/4가 모두 활성화돼 메인과 함께 CPU를 사용하고 있었다. 기본 도구의 종료 안전검사에 막힌 Editor 강제 종료는 실행하지 않았고, Unity Multiplayer Playmode의 Deactivate API로 세 가상 플레이어만 비활성화했다. 메인 Editor는 유지한다. 다음은 측정 중 Unity 도구 요청 없이 수집한6초 튜토리얼 샘플이다.

| 구성 | 프레임 중앙값 | p95 | 최대 |
| --- | --- | --- | --- |
| 가상 Editor3개 활성 | 5.89ms | 6.93ms | 49.65ms |
| 가상 Editor3개 비활성 | 3.82ms | 7.76ms | 36.31ms |

비활성화로 중앙값은 개선됐으나 p95는 개선되지 않았다. 단일 짧은 Editor 표본으로 사용자가 겪은 모든 랙의 원인/해결을 확정하지 않는다. 이 튜토리얼은 loopback이며 Relay를 호출하지 않는다. 실제 인터넷 지연, 학원과 동일한 빌드/하드웨어 조건 비교, 장시간 프레임 스파이크 원인은 별도 미검증이다. 초기 조사 중 도구 호출이 섞인 최대1560ms 샘플은 이 비교에서 제외했다.

학원 인계 당시에는 코드/컴파일만 확인했고 실제 플레이는 미검증이었다. 집 후속에서는 실제 진행을 막던 표적 연결 누락을 수정하고, 단일 Editor에서 7구간을 실제 모터 입력과 서버 무기 요청으로 검증했다. 사용자 손 조작으로 느끼는 난이도/설명의 이해도까지 검증했다는 의미는 아니다.

## 수정

- Foundry 씬의 기존 `targetPrefab`은 의도적으로 비어 있었다. 이를 튜토리얼이 재사용해 4구간부터 표적이 전혀 나오지 않았다. 별도 `tutorialTargetPrefab`을 기존 NetworkDamageTarget에 연결하고 NGO 등록을 추가했다. 일반 대기방 표적 수는 기존대로 유지한다. 생성기에도 해당 참조를 반영했으며 전체 맵 생성기는 실행하지 않았다.
- SideScrollDamageTarget은 기존 서버 유효성/피해 적용 후 실제 사수와 탄종을 `Damaged` 이벤트로 전달한다. 튜토리얼은 자기 표적에만 구독하며 정리 때 해제한다. 추가 RPC나 무기 피해/간격 변경은 없다.
- 일반탄/R/G 구간은 해당 탄종으로 표적을 마무리해야 한다. 일반탄을 한 번 쓰고 R로 처치하거나 G를 발사만 하고 다른 탄으로 처치해 통과하는 흐름을 차단했다.
- S 밀치기는 실제 S 명중 이벤트에서만 발생한다. 앞서 S를 빗맞히고 일반탄을 맞혀도 밀리지 않는다. 기존의 튜토리얼 전용 물리 표적이며 일반 적 넉백 규칙 변경이 아니다.
- 더블점프는 지정된 높은 발판에 착지해야 한다. 점선 하강은 그 발판에서 실제 모터의 `TryDrop` 성공이 있어야 하며, 앉아서 걸어 떨어지는 것은 통과하지 않는다.
- 의료패드는 지정 위치/반경과 실제 접지를 함께 확인한다. 연습 보충/실제 경기 특수탄 수급 안내는 유지했다.
- 안내 왼쪽/상태 오른쪽/이동 버튼 아래로 배치하고 중복 연결·체력·탄약 패널을 튜토리얼에서 통합했다. UI 포인터 차단 영역도 같은 사각형을 사용한다. 카메라를 내려 바닥과 캐릭터가 하단 버튼에 가려지지 않게 하고 오른쪽 학습 대상을 더 보여준다. 월드 글자 크기와 의료 표지 높이를 조정했다.
- 로컬 시작이 false를 반환하면 임시 튜토리얼을 정리한다. 해당 네트워크 시작 실패는 강제로 재현하지 않았다.

## 재현과 근거

최종 1366×768 실행 결과 **PASS / 61개 확인 항목**. 앞선 1577×415 확장 검사도 PASS. 최종 컴파일/Console 오류0, 재생 정지 및 저장 씬 clean을 확인했다.

저장된 Foundry 씬의 Edit Mode에서 `Tools > Right Walk Prototype > Verify Offline Tutorial` 실행. 독립된 `ArenaTutorialReview.cs`가 검사하며 기존 다인용 Actor는 사용하지 않는다. 결과는 `LocalTools/Analysis/Tutorial/result.txt`, 진행은 `progress.txt`, 01~08 PNG에 저장한다. LocalTools는 Git 제외일 수 있어 필요하면 별도로 전달한다.

7구간을 순서대로 실행하며 이동/점프/하강은 `SetInput`과 실제 물리를 사용한다. 사격은 `SetAimTarget`, 탄종 선택, `RightFacingShotPreview.Fire`로 실제 탄약/교체/재발사 대기와 서버 판정을 통과한다. G는 예측 궤적에서 도달 가능한 조준점을 찾은 뒤 실제 발사/비행/폭발로 표적 파괴와 자해를 확인한다.

확인 범위:

- solo Waiting/1인/경기 시작 금지, UGS Uninitialized, 전투 적 없음.
- 7구간 실제 달성, 일반탄 자동충전, 일반탄 고체 차단/R 관통, S 낙하, G 엄폐물 넘기/자해/패드 완전 회복.
- 낮은 발판만 착지, 앉아 걸어 내려오기, 일반탄 후 R 처치, S 빗맞힌 뒤 일반탄 명중은 오인 통과하지 않음. G 구간의 다른 탄 처치는 명시적인 서버 피해 fixture로 거절 확인했다.
- 패드 밖 자동 회복 없음, 재시도와 완료 이력, 완료 화면, 혼자 연습 전환, 원래 대기방 표적 수와 튜토리얼 지형 정리.
- 일반 로컬 호스트 solo=false/최소2인, 일반 대기방의 회복 지급 거절.
- 재입장 시 달성 초기화, 낙하 복귀와 무달성, 메뉴 중 이동 정지, 전 구간 건너뛰어도 달성0, 로비 종료 정리. 낙하만 명시적으로 위치 fixture를 사용했다.
- 화면 1577×415 및 1366×768의 안내/상태/플레이 공간 스크린샷 육안 확인. GUI 버튼의 실제 마우스 클릭 전체를 자동화한 검사는 아니며 전환 기능은 공개 메서드 경유다.

초기 검사에서는 표적 연결 누락을 발견했다. 확장 검사 중 S 빗맞힘→일반탄 검사에서 탄환 도착 전 0.3초에 Hits를 읽는 도구 오류가 있었고, 실제 Hits 증가를 기다리도록 수정했다. 당시 뒤늦게 도착한 일반탄은 Hits=1/속도0/미달성으로 정상 동작했다. 생산 탄속이나 허용 오차를 바꿔 검사에 맞추지 않았다.
