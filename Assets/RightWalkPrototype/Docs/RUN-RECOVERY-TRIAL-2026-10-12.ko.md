# 달리기 뒤쪽 발 회수 비교

## 표시한 중앙 선 재작성

이전 외곽 윤곽 보정은 사용자 표시 위치와 달랐다. 현재는 무릎 패치와 종아리 사이 중앙 선의 두 시작점을 기준으로, 기존 선 조각을 흰 장갑 주변색으로 제거하고 하나의 직선 스트로크로 대체했다. 기존 v69 기준 두 지점 (255,351), (239,377)을 당시 뒤쪽 무릎 좌표계에서 현재 각 자세로 변환한다. 가려진 다리와 신발은 제외한다. 정지/걷기 WalkStrideTrial과 달리기 RunRecoveryTrial PNG를 직접 수정하며 별도 렌더러나 덮개는 추가하지 않는다.

걷기 정지 프레임0 확대에서 중앙의 끊김이 연결된 것을 확인했다. 알파/크기/프레임 위치는 변경하지 않았다. 두 생성기 마지막에 repair_run_contour.py --fresh 후처리를 추가해 생성본의 최신 백업으로 보정하므로, 아래의 자동 생성 미통합 설명은 현재 더 이상 적용되지 않는다.

## 윤곽 픽셀 보정

사용자 승인으로 Python 직접 이미지 보정을 수행했다. 생성형 편집 결과는 해상도와 세부가 변해 적용하지 않았다. 현재 RunRecoveryTrial.png의 뒤쪽 종아리 파츠 경계를 알파 마스크에서 추출해 중간 구간의 끊긴 검은 윤곽을 연결했다. 앞쪽 다리에 가려진 부분은 제외하며, 알파/크기/프레임 위치가 전후 동일함을 검사했다. RGB 변경 13086픽셀. 동작과 관절 좌표는 바꾸지 않았다.

도구: LocalTools/Analysis/repair_run_contour.py. 보정 전 이미지: run-before-contour-repair.png. 이 스크립트는 현재 보정 전 백업을 기준으로 동작하므로, 달리기 시트를 재생성한 뒤에는 백업을 최신 생성본으로 교체해야 한다. 자동 생성기에 아직 통합하지 않았다.

## 원본 파츠 기반 연결점 재설정

이전 임의 연결점(-20,-25)과 프레임별 신발 위치 탐색은 폐기했다. 각 종아리 파츠의 불투명 픽셀을 다리 축에 투영하고 실제 끝의 마지막 12px 영역 중심을 연결점으로 사용한다. 신발은 원본 이미지의 입구 안쪽 (350,417)을 연결점으로 사용한다. 각 파츠의 원본 좌표계에서 해당 점을 회전한 뒤 일치시킨다. 종아리 길이, 파츠 윤곽, 걷기와 승인 원본은 유지한다.

40프레임 x 2다리 검사 영역 노출은 평균 8.2625픽셀, 최대 65픽셀로 이전 평균 82.8875/최대178보다 감소했다. 완전 해결 판정은 아니다. 접지 기준은 이제 양쪽 위상0에서 Y458/460이며 이전 Y465 고정은 더 이상 적용되지 않는다. 연결점을 다시 잡으며 밑창 배치가 달라졌으므로 실제 씬 접지는 후속 검증 대상이다. 전체 80자세의 독립 확대 이미지는 run-ankle-audit-0~3.png로 갱신했다.

## 접지 및 앞발 체류 후속 수정

이륙 준비를 위상 0.26에서 0.30으로 늦추었다. 앞으로 회수하는 발목의 가로 이동은 smoothstep 대신 u²를 사용해 착지 직전 가로 속도가 0으로 떨어져 앞발이 머무는 구간을 줄였다. 이륙 회전과 최대 회전은 유지한다.

실제 종아리 끝 28px 영역의 알파와 부츠 알파를 비교해 부츠 배치를 제한 범위에서 보정한다. 접지 위상 0~0.35에서는 부츠 최저 픽셀 Y=465를 유지한다. 이는 기존 접지 기준이며 실제 씬 바닥과의 절대 일치는 별도 확인이 필요하다. 80자세의 검사 영역 노출은 평균 82.8875픽셀, 최대 178픽셀로 완전 해결은 아니다. 양쪽 공중 구간 0.425~0.9 최소 여유 20px, 도달 불가 0. 걷기와 승인 원본은 변경하지 않았다.

## 이륙 회전 완화

걷기와 발목 색 보정은 변경하지 않았다. 공중 회전 추종의 제곱근 사인 함수를 이륙 0.4~0.6 구간의 smoothstep으로 교체하고 0.75~1.0 구간에서 완만하게 해제한다. 최대 회전은 약 83도를 유지한다. 발끝 여유 높이도 이륙 직후 20px에서 시작해 중간에 추가 12px를 확보하고 착지 직전에 줄인다.

앞쪽 부츠의 위상 0.4→0.425 회전은 약 3.4→7.9도이며 이전 약 3.4→33도보다 완만하다. 같은 구간 신발 최저 픽셀은 Y445→446으로 1px 내려가며 이전 16px 하강보다 줄었다. 완전히 단조로운 상승이라고 판정하지 않는다. 양쪽 공중 위상 0.425~0.9 최소 여유는 착지 기준 대비 12px. 40프레임 도달 불가 0. Unity 재생 검사 도중 연결 끊김이 발생했다.

현재 씬은SideScrollRunRecoveryTrial.unity. 기존달리기와걷기는보존하고별도PNG/Frames/씬을만들었다. 이번단계에서는상체균형이나걷기동작을바꾸지않았다. Shift2.4달리기, 해제시1.6걷기다.

접지40%, 주기이동거리1.586914, 골반높이는기존달리기와같다. 발이떨어지는위상0.4에서발목(182,416)으로시작해0.6에서(150,355)로뒤쪽에접어올린후1.0에서(312,430)착지로돌아온다. 원본좌표기준이며좌우반전으로반대방향을지원한다. 회수하는부츠의각도는최대0.6rad(약34.4도), 접지끝각도는0.06rad로줄였다. 기존은초반회수부터앞으로이동했고부츠회전은약9도였다.

발목목표를변경한뒤고정길이2관절IK로허벅지/종아리자세를다시계산했다. 무릎을반대로꺾거나다리를가로로늘리지않는다.40자세x2다리도달불가0. 원본파츠와미세윤곽보존범위는RUN-TRIAL문서의한계와같다.

실제한주기40샘플을렌더해뒤로접힌회수자세와앞으로돌아오는자세를확인했다. 확대된모든발목연결및접지윤곽의정량검사는아직아니다. 이어서좌우걷기/달리기전환,정지/연속조준4.8초관측982회에서속도±2.4, HoldCycle0회, 최대팔접점오차1.192093e-7월드단위. 검사중새콘솔오류0/컴파일실패0.

기록은LocalTools/Analysis/run-recovery-check.csv, run-recovery-runtime-sheet.png 및run-recovery-runtime.gif. GIF는시간간격으로수집한샘플이며반복끝의위치복귀는루프다. 사용자미적승인전비교본이다. 상체 자세는 변경하지 않았다.

재생성:LocalTools/Analysis/bake_run_recovery_trial.py, Unity Tools/Right Walk Prototype/Build Run Recovery Trial. 기존 생성 스크립트의 AST에서 발목 함수, 부츠 배치와 출력 경로를 대체하므로 원래 달리기 출력은 덮어쓰지 않는다.

## 발끝 끌림 수정

발목 연결과 부츠 회전은 유지하고 발 들기 궤적만 수정했다. 이륙 준비를 위상 0.30에서 0.26으로 앞당겼고, 이륙 시 발목 높이를 416에서 402로, 회수 최고점을 355에서 337로 변경했다. 앞으로 돌아오는 구간 초반에는 높이를 유지하고 후반에 착지 높이로 내려온다.

발목 높이만으로는 회전한 발끝의 바닥 침범을 막지 못했다. 원본 부츠의 알파 픽셀을 변환한 가장 낮은 지점을 계산하고, 공중 구간에서 착지 기준 Y=465보다 위에 있도록 발목 높이를 반복 보정한 뒤 고정 길이 IK를 다시 계산한다. 최대 목표 여유는 18px이며 양쪽 40프레임 렌더의 공중 구간 최저 여유는 4px였다. 이는 스프라이트의 착지 기준 대비 검사이며 실제 물리 지형 전체에 대한 충돌 검사는 아니다.

측정 기록은 LocalTools/Analysis/run-boot-clearance.json이다. Unity 실행 40샘플과 GIF를 갱신했고 새 콘솔 오류 및 컴파일 실패는 없었다. 걷기, 상체, 이동 속도와 주기 거리는 그대로다. 사용자 체감 확인 전 비교본이다.

## 발목 연결 및 회전 수정

사용자 지적에 따라 회수 중 부츠가 종아리를 더 많이 따라 돌도록 수정했다. 위의 최대 34.4도는 이전 버전 기록이다. 현재는 접지 중 낮은 회전을 유지하고, 공중 구간에서는 종아리 방향을 부드럽게 혼합한다. 추종 목표는 최대 약 83도이며 실제 부츠 회전은 혼합 비율에 따라 달라진다.

양쪽 모두 같은 원본 부츠를 사용하므로 부츠 회전 기준을 원본 앞쪽 종아리 방향으로 통일했다. 각도 차이는 -pi~pi로 정규화한다. 신발 입구의 연결점(-20,-25)을 기준으로 종아리와 신발의 서로 다른 회전에서 생기는 위치 차이를 보정한다. 앞쪽 10px, 뒤쪽 6px의 입구 보정을 사용한다. 파츠를 자르거나 늘리지 않았고, 걷기와 승인 원본은 변경하지 않았다.

확대 자세 비교와 Unity 실행 40샘플을 확인했다. 검사 중 새 콘솔 오류와 컴파일 실패는 없었다. 확대 비교 도구는 LocalTools/Analysis/inspect_run_boots.py이며 출력은 run-boot-detail.png다. runtime-sheet와 GIF는 이번 버전으로 갱신했다. 연결점은 시각적 보정값이므로 모든 조준각과 화면 확대에서의 최종 미적 승인은 별도로 필요하다.
