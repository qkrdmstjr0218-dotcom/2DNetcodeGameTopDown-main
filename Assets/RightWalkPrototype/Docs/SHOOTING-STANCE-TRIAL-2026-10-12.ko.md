# 사격 대기 하체 시험

## 사용자 평가 후 비활성화

사용자가 다리를 내밀고 유지하거나 이동을 먼저 시작한 뒤 늦게 걷는 문제를 지적했다. 위상 동결(HoldCycle) 중에도 물리 이동이 먼저 시작되고0.4초 역전환을 기다리는 구조가 원인이다. 이 시험은 실패로 기록하며 저장 씬/컴포넌트/Builder에서UseStance 기본값을false로 바꿨다. 다시 활성화해도 이동 감지 시 전환을 즉시 취소하여 기다리지 않게 했다. 즉시 취소는 자세의 순간 변경을 허용하는 방어 수정일 뿐, 이 서기 전환이 자연스럽게 완성됐다는 뜻은 아니다. 현재 기준은 별도 서기 없이 속도1.6의 넓은 보폭 걷기다. 아래 내용은 비활성화 전 시험 기록이다.

SideScrollStanceTrial.unity는 기존 SideScrollStrideTrial을 복사한 별도 씬이다. 기존 보폭 시험과 승인된 아트는 보존한다. 속도1.6 및 상체 조준을 유지한다.

걷기가 기존 양발 착지 자세0/20으로 정리된 다음0.4초 동안 뒤쪽 발, 앞쪽 발 순서로 낮게 옮긴다. 발목 간격을125px에서50px로 줄인다. 골반은 원본y260에서254로 이동해 완전히 곧게 서기보다 약간 굽힌 사격 대기 자세를 사용한다. 두 착지 자세 각각25장 전환을 별도 베이크했다. 첫 프레임은 기존 착지 그림과 동일하다.

다시 이동하면 현재 전환을 거꾸로 이어 기존 착지 자세로 돌아가 걷기를 재개한다. 전환 도중 다시 정지하면 같은 진행도에서 방향을 바꾼다. ShootingStanceTrial의 UseStance를 끄면 기존 착지 자세로 복귀한다. 별도 씬에서 컴포넌트를 제거하면 기존 보행만 사용한다.

RightFacingWalker의 HoldCycle은 새 컴포넌트가 있는 동안만 사용한다. 기존 씬은 기본false다. RightFacingHipLink의 OverrideDropPixels도 기본null이므로 기존 보정은 유지된다. 새 컴포넌트는 실행 순서50에서 표시를 바꾸고 HipLink90/골반Mesh95/조준100/팔110이 뒤따른다.

50자세의 강체 다리IK에서 발 도달 불가0. 실제5초 관측854회에서 좌우속도±1.6, 정지/재출발/빠른 재입력과 연속 조준을 검사했다. 마지막vx=0, StanceProgress=1, Stance_24 유지. 팔 접점 최대오차5.96e-8월드단위. 기록 LocalTools/Analysis/stance-stop-restart.csv, 화면 shooting-stance-game.png. 컴파일 실패0, 검사 후 현재 Unity 콘솔 오류0. 임포트 도중MCP 파이프라인 timeout1회가 발생했으며 재연결/재임포트 후 검사했다.

이는 미적 승인 전의 시험이다. 전환의 발 좌표는 캐릭터 로컬 기준이므로 재출발 때 실제 이동이 시작되면 월드 접지를 완전히 고정하지 않는다. 별도 공중/점프 동작은 없으며 이번 검사는 지상 동작 기준이다. 현재 하체 파츠는 넓은 보폭 시험과 같은 재구성 소스를 사용하므로 최종v72의 모든 미세한 윤곽 정리를 보장하지 않는다.
