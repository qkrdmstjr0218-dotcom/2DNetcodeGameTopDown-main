## 2026-10-25 점선 상자 정정 / 아이템 외형

이전 상자 아트를 모두 같은 실선 프레임으로 적용하면서 기존 외곽 Lower outer cover ±의 통과 가능한 윗면 표시를 가렸다. 사용자가 지적한 뒤, BoxCollider2D.usedByEffector와 PlatformEffector2D.useOneWay에 따라 Case_120_240_Pass를 고르게 수정했다. 실제 통과 설정은 이전 작업에서도 바뀌지 않았으며 이번에도 유지한다. 두 상자의 윗면에만 청록 점선을 사용하고 몸체의 연속된 밝은 외곽은 낮췄다. 생성기에서 통과 상자에 _Pass가 없는 경우 저장을 거절한다.

아이템은 Ammo_S/R/G를 탄약 캡슐로 바꾸고 각각 탄피/탄두/유탄 그림과 큰 S/R/G를 함께 쓴다. 회복은 손잡이 달린 흰 구급함/녹색 십자, 보호막은 파란 방패 모듈이다. 기존 색과 회복+25/보호막+50 문구를 유지한다. 근처 엄폐물처럼 보이지 않도록 작은 닫힌 모서리 형태로 구별한다.

`ArenaPickupArt`는 기존 MakePickupVisual의 그림 부분만 교체한다. Resources/FoundryArt/Pickup_*.png와 TextMesh를 사용하고 리소스가 없는 경우 기존 도형으로 돌아간다. AmmoPickup/서버 지급/획득 범위/흔들림/낙하/재생성/만료 점멸은 변경하지 않았다. 탄약 그림은 기존 .725×.725, 회복/보호막은 .7×.525의 접촉 외곽 안에 넣었다. 생성 소스는 AppliedFoundryArt/build_pickups.cjs다.

ArenaPickupContactReview 실제 solo PASS: 상체/발/경계/앉기 접촉, 원거리 거절, 실제 탄약1/회복25/보호막50 지급, 만량 시 아이템 보존, 5종 새 아트 연결. LocalTools/Analysis/PickupContact/result.txt 및 pickup-art.png / passable-case.png. 위쪽 5개 아이템 줄은 비교 촬영을 위해 공중에 둔 fixture이며 실제 스폰 배치가 아니다. 대기실 연습 상자는 이번 대상이 아니며, 실제 멀티/빌드 검증은 하지 않았다.

## 2026-10-25 상자 외형 후속

사용자가 상자 디자인 누락을 지적하여 기존 엄폐/발판 상자11개에도 금속 케이스 아트를 적용했다. 모서리 프레임·운반 손잡이·기계식 잠금장치·넓은 패널을 넣고, 반복 홈/점선형 장식은 넣지 않았다. 가로세로 비율5종을 따로 작성하여 큰 잠금장치가 길게 늘어나지 않게 했다. 바닥에 놓인 상자 위치나 높이·폭은 바꾸지 않았다. 탄약 픽업 S/R/G 아이콘은 별도이며 이번 대상이 아니다.

`FoundryCoverArtBuilder`는 기존 렌더러만 숨기고 Collider2D와 ArenaCover는 유지한 채 아트 자식을 붙인다. 기존 상자11개 전후 충돌 변환/크기/재질/flags 동일, 아트 XY 외곽과 기존 콜라이더 일치 검사PASS(case-geometry.txt). 첫 검사는 SpriteRenderer의 표시용 Z두께 .2를 2D 콜라이더의 Z0과 비교해 거절했으므로 XY 비교로 정정했다. 실제 충돌/그림 XY가 어긋난 문제는 아니었다. 생성 소스는 AppliedFoundryArt/build_cases.cjs, 게임 자산은 Resources/FoundryArt/Case_*.png이며 전체 Foundry 생성기의 기존 아트 단계에도 연결했다.

실제 solo 보급고 촬영은 LocalTools/Analysis/FoundryArt/depot-cases.png. 적 위치는 기존 촬영 fixture이고 자연 스폰은 아니다. 첫 전체 상자 검사는 런타임 대기방 x100의 기존 연습용 상자까지 포함해 실패했으므로 실제 전투 맵 범위로 검사 대상을 한정했다. 이번 작업 대상은 전투 맵11개이며 대기방 연습 상자는 별도다. 별도 멀티/빌드 검증은 하지 않았다.

2026-10-25 사용자 진행 승인으로 시안을 게임에 연결했다. 외부 생성형 AI를 사용하지 않았으며, 승인한 수작업 SVG에서 부품별 PNG를 내보냈다.

## 적용 범위

- 지상 로봇: 갈색 장갑·궤도·범퍼·붉은 센서. 기존 Aim 방향을 따라 몸체를 좌우 반전하며, 기존 돌진 예고는 별도 화살표와 센서 점멸로 유지한다.
- 터렛: 고정 받침과 회전 포탑/포신/센서를 분리했다. 기존 서버 조준값으로 회전한다.
- 전투 드론: 양측 덕트 추진기·중앙 센서·기관포를 연결했다. 하부 기관포 시안을 그대로 낮추면 서버 발사 위치와 어긋나므로 몸체를 납작하게 조정하고 센서보다 낮은 기존 발사축에 포신을 맞췄다. 투사체 시작 위치나 공격 능력은 바꾸지 않았다.
- 지원 드론은 기존 화물/방패 외형을 유지한다.
- 맵은 첫 적용 단계로 중앙 보급고 주변 x±13, 중층6.8~상층13.6 배경에 철골·배전반·배관 아트를 넣고, 양쪽 접속 바닥/상층 면을 연속 금속 면으로 정리했다. 보급고 기존 엄폐물은 같은 금속 팔레트로 바꾸고 크기는 유지했다. 배경 그림은 콜라이더가 없다.
- 반복 홈이 점선처럼 보인다는 피드백을 반영해 전체 맵의 옛 Grate opening/Deck joint 장식만 숨겼다. 통과 가능한 윗경계의 점선은 유지하며, 생성기도 내부 반복 홈을 더 이상 만들지 않는다.

맵 전체의 배경 미술을 완성한 단계는 아니다. 중앙 구역의 실제 화면을 기준으로 사용자 가시성 검토 후 같은 방식을 확대할 수 있다.

## 구현

`ArenaEnemyArt`가 Resources/FoundryArt의 부품을 읽고 `ArenaPatrolEnemy`의 기존 bodyRoot/포신/센서/피격/등장/사망 흐름에 연결한다. Resources 경로로 빌드 포함을 보장하며, 리소스가 없는 옛 환경은 기존 도형을 사용한다. 피격 효과는 전용 스프라이트 셰이더의 _HitFlash로 표시한다. 동일 재질을 공유하고 플래시 시작/종료 때만 MaterialPropertyBlock을 갱신한다.

`FoundryArtBuilder.Apply`는 현재 저장된 Foundry 씬만 수정한다. 새 지형/장애물/충돌체를 만들지 않는다. 전후 BoxCollider2D의 인스턴스·변환·크기·오프셋·활성·effector/trigger·재질을 비교하고 같을 때 저장한다. 전체 맵 재생성은 하지 않았고, `RelayFoundryBuilder` 끝에도 같은 미술 단계를 연결했다.

자산 생성 원본/재현 절차는 LocalTools/ArtReviews/AppliedFoundryArt/export_assets.py, render_assets.cjs에 있다. Sprite 원점과 PPU256을 부품끼리 공유하며, 드론 안테나 여유를 위해 몸체 캔버스만3유닛으로 늘렸다. 배경 PPU80, mipmap 없음, bilinear/uncompressed로 사용한다. 게임 캐릭터 아트/리그는 바꾸지 않았다.

## 2026-10-25 일반 추격 방향 수정

사용자가 평지에서 로봇이 뒤로 쫓아온다고 확인했다. 일시정지한 실제 상태에서 Velocity.x=-1.2인데 Aim.x=1 또는0인 사례를 확인했다. 일반 지상 내비게이션은 무기/돌진 Aim을 계속 갱신하지 않으므로 외형이 그 값을 따르면 반대로 향한다. ArenaPatrolEnemy는 일반 Roaming 시 실제 Velocity.x로 그림만 반전하고, 정지(.02이하)는 마지막 방향을 유지한다. 돌진 준비/돌진과 기존 비Roaming 표시 fixture는 Aim 방향을 유지한다. 이동/AI/충돌/피해/네트워크 필드는 변경하지 않았다.

FoundryArtReview에 실제 좌우 평지 추격 검사를 추가했다. 적/플레이어를 지정된 빈 평지에 둔 뒤 서버 내비게이션으로 이동시키고, 반대 방향 Aim을 남겨둔 상태에서 속도와 그림 방향 일치를6회씩 확인PASS. 정지 방향 보존·준비/돌진 방향 고정 및 기존 포신/피격/등장/파괴 검사도PASS. 최초 검사에서는 실제 AI가 사거리 안에서 즉시 돌진 준비로 전환하여 일반 추격 검사 조건이 깨졌다. 검사 중에만 돌진 범위를0으로 격리하고 기존2.8로 복원했다. 실제 돌진 방향은 별도 표시 상태 fixture로 확인했다. 이전 검사는 정지한 미술 fixture의 Aim 반전만 확인해 이 일반 추격 문제를 발견하지 못했다. 결과는 LocalTools/Analysis/FoundryArt/result.txt, ground-facing.csv 및 좌우PNG. 실제 멀티/빌드는 이번 미검증.
