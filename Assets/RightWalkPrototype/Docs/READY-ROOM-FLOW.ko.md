# 준비 공간과 경기 시작 · 2026-10-20

현재 진입 씬은 `Assets/RightWalkPrototype/Scenes/Network/RelayArenaPrototype.unity`다. 기존처럼 Main Editor에서 Local Host, 같은 씬의 가상 플레이어에서 Local Client를 누르면 작은 준비 공간에 모인다. 연결은 기존 localhost:7783 시험 방식이다.

## 사용 흐름

1. 2~4명이 준비 공간에 참가한다. P 번호, 방장, 본인, 준비 여부를 명단과 캐릭터 위에서 확인한다.
2. 각자 **준비**를 누른다. 다시 **준비 취소**할 수 있다. 취소는 자기 상태만 바꾼다.
3. 방장까지 전원 준비하면 방장의 **경기 시작** 버튼이 활성화된다. 준비 상태에서도 이동·점프할 수 있다. 이 공간에서는 일반탄/샷건 사격과 넉백을 연습할 수 있다. 피해는 받지만 서버가 체력을 최소1로 제한하여 사망하지 않는다. 일반탄은 경기와 같은 자동충전, 샷건은 대기방에서만 사격 중단2초 뒤2초마다1발 보충되며 경기 진입/대기 복귀 때 채워진다. 마우스 제한은 해제하고 준비/시작/퇴장 UI 위의 발사 입력은 막는다.
4. 전환 화면을 거쳐 기존 전투맵에 들어간다. 전원 도착 확인 뒤 **3 → 2 → 1 → 시작!**을 표시하며 그동안 이동·사격·피해·득점을 차단한다. 경기 시간은 카운트다운이 끝나야 흐른다. 기본 경기는 기존 점유 모드 3분이며 새 생명, 최대 체력·스태미나·산탄 잔량, 초기 점수와 시작 위치로 출발한다.
5. 종료 시 결과를 확인한다. 방장의 **대기방으로 돌아가기**로 함께 복귀하고, 준비·점수·체력 등을 초기화하여 다음 판을 준비한다. 결과창에서 준비 절차를 건너뛴 즉시 재시작은 없다.

준비 공간의 **방 나가기**, 경기 중 오른쪽 위 버튼 또는 ESC 메뉴로 연결을 종료할 수 있다. 방장은 **방 닫고 나가기**이며 참가자들에게 기존 호스트 종료 안내가 표시된다. 방장 승계는 없다.

## 현재 규칙

시간 설정의 원본은 `Assets/RightWalkPrototype/ArenaObjectiveMatch.prefab`의 **Respawn Seconds**(현재6)와 **Countdown Seconds**(현재3)다. C#에 같은 기본 숫자를 중복해서 두지 않는다. 실행 시 서버가 프리팹 설정을 읽어 NetworkVariable로 전원에게 공유하며, 부활 처리/각 화면의 남은 시간 표기/검사 대기시간이 같은 값을 참조한다. 시작 카운트다운과 사망 대기는 다른 규칙이므로 각각 독립된 설정이다. 프리팹 수정은 다음 실행부터 적용된다. 10초 부활은 사용자의 검토 의견이며 아직 수치 변경하지 않았다.

시간 단일화 검증 `room-093257/result.txt` PASS:프리팹/서버/4인 설정값 일치, 실제 대기/부활/관전/종료 차단·대기 복귀. 양쪽3단 등반도 함께 통과했다.

- 참가 인원이 바뀌면 대기 중인 전원의 준비를 해제한다. 연결 ID를 기준으로 관리하므로 재입장한 사람이 이전 준비 상태를 물려받지 않는다.
- 경기 시작/경기 중/결과/복귀 전환 동안 새 접속은 이유를 표시하여 거절한다. 대기방으로 돌아오면 다시 참가할 수 있다.
- 경기 중 2명 이상 남으면 계속한다. 1명만 남으면 참가자 부족으로 종료하여 대기방 복귀가 가능하다. 혼자 준비해도 시작할 수 없다.
- 시작과 복귀는 서버에서 검증하며 중복 시작, 참가자의 직접 시작, 다른 참가자의 준비 변경을 허용하지 않는다.
- 경기 중 사망하면 서버 시각 기준 **6초 뒤 자동부활**한다. 사용자가3초는 너무 짧다고 평가하여 늘린 임시 수치다. 수동 복귀로 시간을 건너뛸 수 없다. 부활은 본인의 시작 위치와 새 생명/최대 체력·스태미나·산탄 잔량을 사용한다. 종료된 경기에서는 자동부활하지 않는다.
- 부활 대기 중 카메라는 생존 플레이어를 따라가며 화면 아래 **이전/다음** 버튼으로 관전 대상을 바꾼다. 대상이 사망/퇴장하면 다른 생존자를 선택한다. 생존자가 없으면 안내를 표시하고 본인 주변을 보여준다. 부활하면 본인 카메라·조작으로 돌아온다. 관전자 전용 접속은 이번 범위가 아니다.
- 전원 재경기 투표, 방 검색 로비, 튜토리얼, 모드 선택, 정비 기능은 후속 설계 대상이다. 이번에는 연결된 방 하나의 준비→경기→결과→복귀를 구현했다.

## 구현 범위

현재 NGO `EnableSceneManagement=false` 구조를 유지한다. 같은 Unity 씬에서 전투맵과 분리된 x=100 준비 공간을 모든 실행 화면에 만들고, 서버 단계에 따라 화면 전환과 새 생명 세대의 위치 초기화를 수행한다. 전투맵을 다시 만드는 방식이 아니므로 기존 경사로, 다리, 사격과 캐릭터 미술을 보존한다. 캐릭터 실제 크기를 변경하지 않고 준비 공간 카메라만 한눈에 보이게 조정했다. 준비 공간 미술은 임시 배치다.

준비 명단은 최대 4명의 단일 NetworkVariable 스냅샷이다. 여러 명의 동시 재입장에서 초기 명단과 추가 이벤트가 중복 적용될 수 있던 NetworkList 시안은 교체했다. 옛 전투·지형 집중 검사 도구는 `session.useReadyRoom=false`를 명시하여 기존 시험 절차를 유지한다. 일반 실행은 준비방 흐름이 기본이다.

검사 메뉴: **Tools → Right Walk Prototype → Verify Ready Room**. 결과와 화면은 `LocalTools/Analysis/NetworkCombat/room-*`에 기록한다. 검사에서는 대기 시간을 줄이려고 실행 중 경기 시간을 단축하며, 저장된 기본 3분 설정을 바꾸지 않는다.
