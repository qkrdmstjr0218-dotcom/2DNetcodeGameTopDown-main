# 해킹 구역 점유 · 첫 경기 시험

씬: `Assets/RightWalkPrototype/Scenes/Network/RelayArenaPrototype.unity`.
모든 Virtual Player도 같은 씬을 열어야 한다. **2026-10-20부터 일반 실행은 [준비 공간 흐름](READY-ROOM-FLOW.ko.md)을 사용한다.** 접속 후 2~4명 전원 준비 → 방장 시작 → 경기 → 결과 → 방장 대기방 복귀 순서다. 아래의 즉시 시험 시작 절차는 준비방을 명시적으로 끄는 자동 검사 도구에서만 유지한다. 준비 공간에서는 이동/점프만 허용하고 사격/피해는 차단한다.

## 시험 규칙

- 개인전 시험, 기본3분. 표시 구역 안에 발 중심이 들어온 접지 상태의 생존자가 혼자 있으면1초당1점. 사격은 계속 가능하고 F 유지 입력은 없다.
- 구역 안에2명 이상이면 모두 득점을 멈춘다. 점수는 누적하며 빼앗겨도 초기화하지 않는다.
- 점프/공중 체류는 점유로 인정하지 않는다. 아래층, 사망/복귀 적용 전 위치는 득점·경합에서 제외한다.
- 후보는 하단 중앙(0,0), 서쪽 중단(-10.5,3.2), 상단(2.5,6.4), 동쪽 중단(10.5,3.2). 빈 공간 무작위 생성이 아닌, 미리 배치한 안전한 바닥 지점이다.
- 순서는 하단 → 서쪽 중단 → 상단 → 동쪽 중단 순환.30초마다 이동하고5초 전에 다음 구역을 희미하게 표시한다. 첫 시안은 동선 비교를 위해 고정 순서이며 랜덤 순서는 아직 넣지 않았다.
- 현재 구역은 청록(비어 있음), 녹색(단독 득점), 황색(경합). 화면 중앙 상단에 현재/다음 구역과 경기 시간, 오른쪽에 P번호별 점수.
- 시간 종료 시 누적 점수가 가장 높은 참가자가 승리. 차이가.05점 이내면 공동1위, 전원0점이면 무승부. 표시값은 소수 첫째 자리, 내부 계산은 초 단위 소수값이다.
- 종료 후 이동/사격 입력을 차단하고 마우스 제한을 해제해 결과를 표시한다. 서버에서도 종료 후 새 사격과 지연된 피해를 거절한다. ESC 메뉴/연결 종료 가능. 호스트가 다시 시작하면 점수·체력·생명 세대·시작 위치를 재설정한다. 자동 부활은 추가하지 않았으며 경기 중 기존 본인 복귀 버튼을 사용한다.
- 진행 중 퇴장한 사람의 점수는 제외하며 재접속은0점부터 새 참가로 처리한다. P번호가 재사용돼도 이전 점수는 물려받지 않는다. 중도 접속은 현재 지점/점수/마감 시간을 받는다. 종료 후 중도 접속은 결과를 보고 다음 경기부터 참가한다.

## 구현 범위

서버가 구역·점수·시계를 결정하는 `ArenaObjectiveMatch` 네트워크 프리팹을 세션 시작 시 생성한다. 후보와 표시만 씬에 배치한다. 플레이어 이동 복제는 기존 소유자 기반 방식이며 별도의 이동 부정행위 방지는 이번 범위가 아니다.

맵/캐릭터 배율·엄폐 시안·원래 시험 씬은 유지한다. 달리기 스태미나 소모와 본인 잔량 표시를 추가했다. 점프 자체의 소모는 없다. 상세 수치는 RELAY-ARENA-PROTOTYPE.ko.md의 달리기 스태미나 시험 항목을 따른다. 수치/개인전/고정 순서/바닥 점유 방식은 테스트 후보이며 최종 승패 규칙 수용을 뜻하지 않는다.

## 검증

편집기 메뉴 `Tools/Right Walk Prototype/Verify Hacking Objective`로 사전 컴파일한 검사 실행. 실행 중 MCP CodeDom 컴파일을 사용하지 않는다. 검사 후 `Assets/RightWalkPrototype/Tests/ObjectiveReviewRequest.json`과 `.meta`를 제거한다.

최신 결과: `LocalTools/Analysis/NetworkCombat/objective-110225/result.txt` PASS.4인에서 단독/경합/사망·복귀/다른 층 제외, 구역 내 사격, 예고·이동 일치, 재접속 상태·0점, 종료 점수·승자 일치 및 서버 전투 거절, 재시작/0점 무승부/호스트 종료 상태 해제를 확인했다. preview/result 캡처도 보존했다.

## 경사로 점유 판정 후속 수정
기존 발높이±.22 제한을 제거했다. 이제 실제 표시 사각형 안의 발 중심을 기준으로 하므로 경사로 위에서도 인정한다. 머리나 총이 밖으로 나와도 무관하며 가로는 캐릭터 중심, 세로는 발 높이를 사용한다. 바닥 접촉 여유.05 외에는 실제 표시 bounds와 일치한다. 접지 조건은 유지하여 점프/낙하 중 득점·경합은 중단하고 착지하면 다시 인정한다. 위아래 다른 층과 시체는 제외한다.

최신 집중 검사 `objective-114604/result.txt` PASS.4인에서 실제 경사로의 호스트/클라이언트 득점, 점프 중지/착지 재개, 좌우 경계 안·밖, 아래층/구역 위 발판 제외와 시체 제외/전원 점유 상태 동기화를 확인했다. 편집기 메뉴 Verify Objective Bounds, ramp-scoring 캡처 보존. 기본 입장 흐름은 움직일 수 있는 준비 공간에서 전원 레디 후 경기맵으로 이동하는 후보도 있으며 아직 구현하지 않았다. 상호작용 제한의 점유자 이점 완화 목적도 재검토 대상이다.


## 해킹 지점 방향 안내 (2026-10-20)

현재 지점은 청록색, 이동 예고 중인 다음 지점은 황색과 `다음 · N초 후`로 구별한다. 화면 밖이면 가장자리 방향 화살표, 화면 안이면 구역 위 마름모를 표시하며 지점 이름과 직선 거리를 함께 보여준다. 거리는 임시 월드 단위이며 경로 길이가 아니다. 기존 시험 HUD/체력·탄약 패널과 안내끼리의 겹침을 피한다. 메뉴·전체맵·대기·종료에서는 추가 안내를 숨긴다. 다음 구역 월드 표시도 황색이다. 서버의 기존 경기 상태/예고 시간을 읽는 표시 기능이며 득점 조건과 지점 활성 시점은 그대로다. 단독 호스트 UI 화면 검증: LocalTools/Analysis/NetworkCombat/guide-053606.
